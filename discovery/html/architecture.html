vLLM V1 Architecture Process layout, per-step flow, and module dependency map.

vLLM V1 is a multi-process serving engine. The API server handles HTTP/OpenAI requests, marshals them to an EngineCore process via ZMQ, and the EngineCore drives one or more GPU workers through a tight schedule() → execute_model() → update_from_output() loop.

The diagrams below highlight where evolutionary code search has the highest leverage: orange nodes are the top-10 evolve targets, blue nodes are stable infrastructure, and dashed edges mark cross-process boundaries (ZMQ / NCCL / RDMA / NIXL).

Per-Step Request Flow

What happens on every EngineCore tick. schedule() is called with the current waiting + running queues, produces a SchedulerOutput, the worker runs execute_model(), and update_from_output() closes the loop with sampled tokens, KV-cache updates, and spec-decode acceptance counters.

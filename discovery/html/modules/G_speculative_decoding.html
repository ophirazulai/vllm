Evolve Locations

Adaptive draft-length / acceptance policy risk: low–medium

vllm/v1/spec_decode/llm_base_proposer.py · ngram_proposer.py

(a) Per-request adaptive num_speculative_tokens (currently a static config); (b) ngram prompt_lookup_min/max heuristic; (c) the EAGLE chain-vs-tree topology and pruning rule. Acceptance-rate–aware draft length is a natural fit because the objective (token-acceptance × throughput) is a simple scalar with a Bernoulli-mixture reward signal.

What to evolve
Function (acceptance_history, queue_state, request_priority) → num_speculative_tokens.
Evaluator
examples/offline_inference/spec_decode.py on InstructCoder + MT-Bench (already in repo as PR #18847).
Metric
Tokens/sec (already encodes the AL × draft-overhead trade-off); break ties by acceptance length AL.
Risk
Low–medium — wrong draft length only affects latency, never correctness, because the rejection sampler preserves the target distribution.

EAGLE tree topology & pruning risk: medium

vllm/v1/worker/gpu/spec_decode/eagle/

EAGLE-2 dynamic draft trees and EAGLE-3 training-time test pruning logic.

What to evolve
Tree branching factor + pruning threshold as a function of confidence histogram and step latency.
Evaluator
End-to-end serving with EAGLE-3 + CUDA graphs.

ngram_proposer.prompt_lookup_min/max heuristic risk: low

vllm/v1/spec_decode/ngram_proposer.py · ngram_proposer_gpu.py

Static n-gram match window currently. Easy to evolve into a context-aware pair.
